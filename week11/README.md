# EdgeMemo 邊緣備忘錄 — 五分鐘解說報告

> 口語化演講稿｜預計 5 分鐘｜網站：<https://edgememo.edgememo.workers.dev>

## 開場（0:00–0:30）

大家好，我今天要介紹的是第九週做的網站，名字叫 **EdgeMemo**，中文是「邊緣備忘錄」。它是一個打開瀏覽器就能寫筆記的小網站，特別的地方是：它沒有傳統伺服器，而是跑在 Cloudflare 的邊緣節點上。大家現在可以一邊聽、一邊打開這個網址：<https://edgememo.edgememo.workers.dev>。

## 一、為什麼做這個網站（0:30–1:00）

我想要一個「打開就能寫」的個人備忘錄牆，不要登入、不要等待、手機也能用。畫面是一面卡片牆，每一則筆記就像一張有色紙，重要的可以釘選在最前面，忘記放在哪裡時可以直接搜尋。整體用溫暖的紙張色調，亮色、暗色模式會跟著系統設定自動切換。

## 二、網站是怎麼做出來的（1:00–2:30）

製作過程我分成五步。

第一步先設計資料表。在 `schema.sql` 裡定義一個 `notes` 表，欄位有 id、標題、內容、顏色、是否釘選，以及建立與更新時間。標題限制 120 字、內容 20,000 字，顏色只能是六種，釘選只能是 0 或 1，這些限制直接用資料庫的 `CHECK` 條件寫死。另外加了索引，讓「釘選優先、更新時間新到舊」的排序更快。`seed.sql` 則放了六則範例筆記，用 `WHERE NOT EXISTS` 避免重複匯入。

第二步做後端 API。核心是 `src/worker.js`，它處理 `/api/notes` 的新增、查詢、修改、刪除，以及統計和健康檢查。所有 SQL 都用 `.bind()` 參數化查詢，搜尋時還會跳脫 `%`、`_` 這些萬用字元，避免注入問題。錯誤也分成 400、404、405、500 等情況，回應統一用 `{ data }` 或 `{ error }` 的格式。使用者沒輸入標題時，程式會自動拿內容第一行當標題。

第三步做前端。前端是純 HTML、CSS、JavaScript，沒有用框架。`index.html` 放頁面骨架和編輯器對話框，`app.js` 負責狀態、卡片渲染、搜尋與編輯互動，`style.css` 負責紙張卡片、響應式版面和亮暗模式。所有使用者輸入都用 `textContent` 輸出，不會被當成 HTML 執行，避免 XSS。

第四步串接設定。在 `wrangler.jsonc` 裡把 D1 資料庫綁成 `DB`，把 `public/` 設成靜態資產，並讓 `/api/*` 優先交給 Worker 處理。找不到的無副檔名路徑會回傳 `index.html`，所以這是一個可以直接重新整理的單頁應用。

第五步是本機測試和部署。本機用 `npm run setup:local` 建表並匯入範例，再用 `npm run dev` 開 `localhost:8787` 測試；確認沒問題後，`npm run deploy` 就部署上線。之後更新也只要再跑一次部署指令。第九週結束後，我還把這個專案打包成 npm 套件 `@fifi1060411/fidog`，那是第十週的延伸。

## 三、使用了哪些工具（2:30–3:00）

工具方面，後端是 **Cloudflare Workers**，負責 API 和路由；資料庫是 **Cloudflare D1**，本質上是跑在雲端的 SQLite；靜態檔案交給 **Static Assets** 走 CDN；本機開發和部署用 **Wrangler** 這支命令列工具；語言是 **Node.js 18 以上的 JavaScript** 加 **SQL**，套件管理用 **npm**。另外我用 **Git** 和 **GitHub** 管理版本，也用 **opencode** 協助寫程式、測試和文件。

## 四、網站要怎麼使用（3:00–4:00）

使用很簡單。打開網站後，按右上角的「新增備忘錄」，輸入標題和內容，選一個喜歡的色紙顏色，需要的話打開釘選，再按儲存；也可以直接按 `Ctrl + Enter`，Mac 則是 `Cmd + Enter`。想修改哪一則，直接點那張卡片，對話框就會帶出原本的內容；刪除會再確認一次，誤刪機率很低。

工具列上有搜尋框，輸入關鍵字會即時同時搜尋標題和內容；旁邊可以切換「全部／釘選」，也可以依六種顏色篩選。頁面上會顯示筆記總數和釘選數量。手機版會把編輯器變成全螢幕，卡片牆改成單欄，操作起來跟電腦一樣順。

## 五、網站有哪些功能（4:00–4:40）

整理一下功能：新增、編輯、刪除備忘錄；六種色紙分類；釘選置頂；即時全文搜尋；顏色與釘選篩選；筆記統計；單頁應用支援直接重新整理；響應式版面；亮暗模式；以及 skip link、對話框焦點管理、`aria-live` 等無障礙設計。安全性上，前端不執行使用者的 HTML，後端驗證長度、型別與顏色，SQL 全部參數化，回應也加了 `nosniff` 和 CSP。以個人使用量來說，Cloudflare 每天十萬次請求、D1 每天五百萬次讀取的免費額度完全夠用。

## 六、限制與結語（4:40–5:00）

最後要提醒的是，目前**沒有登入機制**，任何人打開網址都能新增、修改和刪除，所以不要放敏感資料；如果要公開給多人用，建議再加 Cloudflare Access、Turnstile 或流量限制。搜尋結果目前最多回傳 500 則，資料變多時要改成分頁。

總結來說，這個專案讓我實際練習了邊緣運算架構、前後端分離、資料庫設計、參數化查詢、部署流程，以及文件與套件打包。以上就是 EdgeMemo 的介紹，謝謝大家，歡迎現在打開網站試試看：<https://edgememo.edgememo.workers.dev>。
